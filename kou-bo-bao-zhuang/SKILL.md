# kou-bo-bao-zhuang · Codex 执行 Skill

> 本 Skill 只规定 Codex 在收到已确认的动效施工 Prompt 之后如何执行。
> 不包含需求访谈、内容判断、草图制作或 Prompt 编写工作。
> 施工 Prompt 由对话方在 Skill 之外确认后提供，Codex 不应重新访谈、重新定方向。

## 1. 适用范围

执行：
- 按施工 Prompt 给一段竖屏口播配动效，画面全部由 p5.js 代码绘制。
- 按句切分的普通短动效；模板 F 这类多句话共同铺垫一个结论的长背景层是明确例外，可以跨句连续发展。
- 三种交付形式之一，由施工 Prompt 指定（见第 4 节），不得混用：
  1. 完整图解动效
  2. 满屏背景层
  3. 透明叠加层

不执行：
- 重新决定这段最想让观众记住什么、改变创意方向、重排内容结构。
- 教剪辑、讲剪辑理论。
- 用视频生成模型直接出片、做 3D 动画、做整条无真人出镜的知识片。
- 在施工 Prompt 之外自行增加元素、品牌、数字或流行款式。

## 2. 输入契约

施工 Prompt 通常已包含以下字段。收到后先逐项核对：

| 字段 | 说明 |
|---|---|
| [口播原文] | 本段原话，一字不改。数字、价格、百分比、排名、品牌只用其中出现的。 |
| [实际时长] | 本段实际时长（秒），以及总帧数（秒 × 30）。见第 3 节时间规则。 |
| [动效类型] | 普通型 / 数据型 / 故事型，三选一；或模板 F 长背景层。类型已定，不重新判断。 |
| [元素清单] | 每个元素的名称、数量、文字内容。未列出的元素不画。 |
| [布局与安全区] | 每个元素的坐标范围、大小、层级、安全区。坐标、时长、文字必须可直接替换。 |
| [时间轴] | 每个元素在第几秒出现、移动、停留、退场。 |
| [入场方向和动作] | 入场方向、运动方式、回弹、停留、退场方式。 |
| [输出格式] | 三种交付形式之一，以及本次是否明确要求渲染视频。见 `references/export-spec.md`。 |
| [参考结构草图]（如有） | 仅作结构参考：位置、比例、数量、运动方向、层级。按结构用代码重画，不照抄像素。 |

### 输入缺失时的处理

- 只有在缺少的信息会阻止实现时，才提出最少量的具体问题，并说明缺少哪一项、会挡住哪一步。
- 有小的实现空间时，在施工 Prompt 的约束内选最直接、最保守的实现，不要因此重新设计整段动效。
- 只有技术上无法实现，或要求互相矛盾时，才暂停并说明冲突点和可行的替代方案，不要假装已完成。

### 技术冲突检查（开始写代码前做）

- 时间、帧数、画布、输出格式是否互相一致。
- 元素数量、尺寸与安全区是否放得下；放不下时按第 4 节的交付形式和安全区处理，不擅自缩小关键文字或改动布局。
- 透明叠加层是否要求了不透明背景或普通 MP4 交付（见 `references/export-spec.md`，属冲突）。

## 3. 统一时间规则

时间优先级固定为：

**实际粗剪视频中核对过的时间 ＞ 用户明确提供的实际时间点 ＞ SRT 时间。**

- SRT 只作分句和初步定位工具，不是高于实际视频的最终依据。
- 施工 Prompt 与 SRT 不一致时，以施工 Prompt 中给出的实际时间为准，并在交付说明中注明所用时长与帧数。
- 普通短动效默认按句切分，一句一段，不跨句堆信息。
- 模板 F 长背景层是明确例外：多句话共同铺垫一个结论时，按施工 Prompt 给出的连续时间轴做一个长背景层，不必机械地一句一段。

计算：总帧数 = [实际时长] × 30。时间只用 `frameCount`（秒 = `frameCount / 30`）。

## 4. 统一交付形式

严格按施工 Prompt 指定的类型执行，不得把三种形式混在一起：

| 交付形式 | 执行规则 |
|---|---|
| 完整图解动效 | 可以包含统一字幕、角标和口播小窗。字幕、角标的位置与样式按 `references/style-system.md` 执行，全段一致。 |
| 满屏背景层 | 默认不画字幕、不画人物，只提供背景运动。背景为满屏不透明暖纸底。 |
| 透明叠加层 | 只画需要叠加的卡片、图标或文字，其他区域保持透明。不得加不透明满屏底。 |

- 施工 Prompt 未指定交付形式时，按其 [输出格式] 字段的默认值执行；仍不明确且会改变实现时，按第 2 节提出最少量问题。
- 剪映里的层序、抠像、人物缩放、字幕调整属于施工 Prompt 之外的合成工作，Codex 不在动效文件里实现。

## 5. 固定值（锁死）

- 画布：竖屏 9:16，1080×1920，30 fps。
- 生成：全部用 p5.js 代码绘制，不用生图、不用视频模型、不用外部图片贴图。只输出一个 `index.html`（模板 E 明确要求三方向时除外，见模板 E）。
- 随机种子：`randomSeed` 和 `noiseSeed` 固定，每次打开效果一致。
- 最后 1 秒停住，不退场。
- 声音：全片不加背景音乐。动效文件保持无声。每个主要入场动作只在交付说明里标注 1 项建议音效，见 `references/style-system.md` 的音效对照表；没有动作的句子不标。
- 不编造：数字、价格、百分比、排名、品牌、流行款式，只用 [口播原文] 和施工 Prompt 中已给出的内容。
- 不照抄像素：只根据已确认的结构草图重新用代码绘制，不照抄精修参考图或草稿图的像素。

详细视觉与技术参数不在此重复，执行时按以下文件：

| 需要时读 | 内容 |
|---|---|
| `references/style-system.md` | 六色色卡、三种视觉类型的具体定义、统一视觉规则、音效对照表 |
| `references/p5-foundation.md` | 画布、随机种子、纸纹、网点、撕纸边、投影、手绘线、动作参数、录制接口、自包含与备用方案 |
| `references/export-spec.md` | HTML、WebM、MP4、透明通道的交付规则 |
| `templates/template-[a-f].md` | 本次施工 Prompt 指定的执行模板，只读对应的一个 |
| `examples/xixi-trial.md` | 已跑通的案例与有效技术结论 |

## 6. 执行流程

1. 读取施工 Prompt，确认第 2 节的输入字段是否齐全。
2. 按第 2 节做技术冲突检查；有冲突或缺失到无法实现时，按第 2 节处理。
3. 加载对应的参考文件和模板：先读 `references/style-system.md` 和 `references/p5-foundation.md`，再读施工 Prompt 指定的模板；需要渲染时再读 `references/export-spec.md`。
4. 用 p5.js 编写可运行的单文件 `index.html`。所有占位符统一用清楚的方括号，例如 [实际时长]、[口播原文]、[元素名称]，不要留下没有标签的空白。模板中的坐标、时长、文字必须能被直接替换。
5. 在浏览器中运行并检查效果（见第 7 节）。
6. 修复空白、遮挡、文字溢出、时长错误、穿帮和运行报错。
7. 按施工 Prompt 本次明确要求的格式交付（见 `references/export-spec.md`）。每次都保留可修改的 `index.html` 源文件。
8. 简洁说明交付文件、实际参数（画布、时长、总帧数、帧率、输出格式）和建议音效。

不得引入与当前任务无关的脚本、网络调用或工具。

## 7. 自检（每次交付前对一遍）

- [ ] 画布是 1080×1920 竖屏，30 fps；总帧数 = [实际时长] × 30；最后 1 秒停住。
- [ ] 已检查第 1 帧、中间帧、关键动作帧、最后 1 帧：无空白、无穿帮、文字无溢出、无遮挡关键信息。
- [ ] 颜色没有跳出六色色卡；港蓝只出现在数据段，金色与暖木只出现在升华句（按施工 Prompt 指定）。
- [ ] 数据段能一眼看清最大的数字；故事段能看懂先发生了什么、后发生了什么。
- [ ] 一段只讲一个信息点；模板 F 例外时按其连续时间轴执行。
- [ ] 画面是代码画出来的，没有照抄草稿图或成品图的像素；没有画未列出的品牌 logo。
- [ ] 交付形式与施工 Prompt 一致：背景层无字幕、无人物；透明层其余区域透明。
- [ ] 动效文件无声；建议音效已按对照表标注在交付说明里。
- [ ] 如本次要求渲染，已按 `references/export-spec.md` 检查分辨率、帧率、时长、最后停帧和透明通道；无法完成的格式已如实说明，未声称完成。

## 8. Codex 不做的事

- 不重新决定内容重点，不擅自改变创意方向，不重排时间轴。
- 不编数字、价格、百分比、排名、品牌或流行款式。
- 不把数据卡做成深色商务底；数据卡仍放在暖纸底上，用港蓝为主色。
- 不在同一段里同时用数据型和故事型（施工 Prompt 明确指定模板 F 或分段结构时除外）。
- 不为平淡段加满屏动效；平淡段的任务是让人听清。
- 不加背景音乐，不用厚重的电影感砸点。
- 不自动下载、不始终录制、不自动批量运行脚本；渲染只在施工 Prompt 本次明确要求时执行。
- 不把需要透明通道的素材直接转成普通 MP4。
