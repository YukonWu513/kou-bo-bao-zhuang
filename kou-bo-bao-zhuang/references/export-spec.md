# 导出规范 · export-spec

> 每次都保留可修改的 `index.html` 源文件。
> 只有当施工 Prompt 本次明确要求视频素材时，才执行渲染。
> 不要把“自动下载”“始终录制”“以后批量运行脚本”当作默认行为。

## 1. 交付矩阵

| 施工 Prompt 的 [输出格式] | 交付 |
|---|---|
| 完整图解动效，未明确要求视频 | 只交付 `index.html` |
| 完整图解动效，明确要求视频 | 交付 `index.html` + MP4（1080×1920、30 fps） |
| 满屏背景层，未明确要求视频 | 只交付 `index.html` |
| 满屏背景层，明确要求视频 | 交付 `index.html` + MP4（1080×1920、30 fps） |
| 透明叠加层，未明确要求视频 | 只交付 `index.html`（透明背景） |
| 透明叠加层，明确要求视频 | 交付 `index.html` + 带透明通道的 WebM |
| 同时需要兼容版（施工 Prompt 明确要求） | 在上面基础上，额外提供预合成背景后的 MP4，并明确标注为兼容版，不是透明版的替代品 |

## 2. 格式规则

- 不透明的满屏背景或完整图解：导出 1080×1920、30 fps 的 MP4，并保留 HTML。
- 需要透明背景的叠加层：导出带透明通道的 WebM，并保留 HTML。
- 不要把需要透明通道的素材直接转成普通 MP4；透明层转成普通 MP4 会变黑底，属于错误交付。
- 动效文件保持无声；建议音效只写在交付说明里。
- HTML 不是视频，不能直接导进剪映；渲染成视频后才能合成。交付说明里写清这一点，不要让用户误以为 HTML 本身就是可用素材。

## 3. 导出后检查

渲染完成后检查：
- [ ] 分辨率 1080×1920，帧率 30 fps。
- [ ] 时长与 [实际时长] 一致，总帧数正确。
- [ ] 最后 1 秒停住，停在最后一帧。
- [ ] 透明叠加层：透明通道有效，其余区域透明；普通 MP4 兼容版已明确标注。
- [ ] 无空白、无穿帮、无文字溢出。

## 4. 无法完成时

- 如果当前环境无法完成某种渲染或转码，必须如实说明哪一种格式未完成、原因是什么，并交付已经完成的其他文件。
- 不得声称已经完成未完成的导出，不得用其他格式冒充要求的格式。
- 批量导出脚本只在施工 Prompt 本次明确要求时才提供或执行；未要求时不提供、不执行。

## 5. 交付说明格式

每次交付用简洁说明，包含：
- 交付文件清单
- 实际参数：画布 1080×1920、30 fps、[实际时长]、总帧数、输出格式
- 建议音效：按 `references/style-system.md` 对照表，每个主要入场动作 1 项
- 未完成项（如有）：如实说明
