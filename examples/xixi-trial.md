- [实际时长]：24.2 秒，共 726 帧；只播一遍，不循环，播完停在最后一帧。

- [顶部中心 x]：125、295、465、635、805、975；顶部 y=40–280；图标之间留约 20 px 的缝。

## 2. 时间规则验证

- SRT 只有 8.2 秒，与实际视频 24.2 秒不一致。
- 按统一时间规则执行：以实际视频时间为准，SRT 只作分句参考。
- 教训：施工 Prompt 必须写明实际时长，不要只信 SRT。

## 3. 已验证有效的技术规则

- 图标被人物遮挡没关系，可以大一点；上升路线中间也可以走，不要只走两边，不要把图标缩小。
- 上升 + 顶部聚集的结构贴合“3 → 1”的内容。
- 贴纸白边 + 异形有效：白边 12 px，沿着图标本身轮廓走，不是圆形底座；足球是圆的没关系，咖啡杯、画笔、球鞋保持原来形状。
- 落到顶部带小回弹，之后饱和度降 15%，透明度 90%。
- 结论卡不放在背景文件里，单独做透明叠加层（另一次执行，另给施工 Prompt）：
  - 位置 x=54–1026，y=1480–1760；暖纸底，圆角 24 px。
  - 文字：“都类似 → / 很难有独特视角”，其中“独特视角”用 #B66E4A 粗体加下划线。
  - 其余区域透明，交付带透明通道的 WebM + HTML。
- 合成说明（不属于 Codex 执行内容，仅作交付背景）：剪映里从下到上为背景层、抠像后的人、结论卡；人物必要时用关键帧从 100% 慢慢缩到 85%，往下移一点，空出顶部；字幕在剪映里调。抠像先试 3 秒，头发丝和耳环最容易出白边。

## 4. 导出结果

- Codex 先交付 `index.html`；HTML 本身不能直接导进剪映。
- 施工 Prompt 明确要求视频时，Codex 在云端录制并返回 WebM（2026-11-11 已验证）。
- WebM 能带透明，适合结论卡；MP4 最通用，但一般不带透明，透明层不直接转普通 MP4。
- 交付说明包含实际参数（1080×1920、30 fps、24.2 秒、726 帧）和建议音效（图标冒出 = 轻 pop，落到顶部 = 轻 tap）。
